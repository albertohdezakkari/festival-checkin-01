# 0 · Festival Check-in en GitHub Codespaces

Vas a ejecutar **Serverless Offline y DynamoDB Local dentro de tu Codespace**. El escritorio del aula solo necesita el navegador y acceso a GitHub. Las herramientas y los datos quedan en el entorno de Codespaces.

## 1. Abre el proyecto en el navegador

1. Abre la [rama local de Festival Check-in](https://github.com/albertohdezakkari/festival-checkin-01/tree/local).
2. Pulsa **Code → Codespaces → Create codespace on local**. Espera a que se abra VS Code en el navegador. GitHub ya abre una copia del repositorio en el Codespace. [Crear un Codespace desde una rama](https://docs.github.com/es/codespaces/developing-in-a-codespace/creating-a-codespace-for-a-repository)
3. Abre **Terminal → New Terminal** dentro de VS Code. Ejecuta los comandos de esta guía ahí.

```bash
pwd
git branch --show-current
ls package.json serverless.local.yml
```

**Antes de avanzar**, busca la rama `local` y los dos archivos. Si abriste un Codespace que estaba en `main`, vuelve al enlace del paso 1 y elige explícitamente `local`.

## 2. Prepara Node y Java en el Codespace

```bash
node --version
java -version
```

Para repetir el montaje del aula, usa **Node 22** y **Java 17 o superior**. Si necesitas Node 22, ejecuta:

```bash
nvm install 22
nvm use 22
node --version
```

Si Java falta o es anterior al 17, instala Java en el Codespace:

```bash
sudo apt-get update
sudo apt-get install -y openjdk-17-jre-headless
java -version
```

Si después de instalarlo sigue apareciendo un Java anterior, elige el ejecutable de Java 17 para la terminal que arrancará DynamoDB:

```bash
fci_java17=$(find /usr/lib/jvm -type f -name java | grep '/java-17-' | head -n 1)
echo "$fci_java17"
```

Cuando aparezca una ruta, ejecuta:

```bash
export FCI_JAVA="$fci_java17"
"$FCI_JAVA" -version
```

Desde la raíz del repositorio, instala las dependencias y descarga DynamoDB Local:

```bash
npm ci
mkdir -p .local/dynamodb
curl -fsSL https://d1ni2b6xgvw0s0.cloudfront.net/v2.x/dynamodb_local_latest.tar.gz \
  | tar -xz -C .local/dynamodb
ls .local/dynamodb/DynamoDBLocal.jar
```

**Antes de avanzar**, comprueba que la última línea muestra `DynamoDBLocal.jar`. [Instalación oficial de DynamoDB Local](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/DynamoDBLocal.DownloadingAndRunning.html)

## 3. Terminal 1 · Arranca DynamoDB

```bash
npm run db:local
```

**Antes de avanzar**, espera a ver `Port: 8000`. Deja abierta esa terminal.

## 4. Terminal 2 · Carga los datos y arranca la API

Pulsa **+** en el panel de terminal para abrir otra. Desde la raíz del mismo repositorio, ejecuta:

```bash
npm run datos:local
```

Cuando veas **`Datos disponibles: evento 1 y usuario-02`**, ejecuta:

```bash
npm start
```

**Antes de avanzar**, espera a ver `Server ready: http://127.0.0.1:3004`. Deja abierta también esta terminal.

## 5. Terminal 3 · Comprueba la lectura y la escritura

Abre una tercera terminal **dentro del Codespace**. Aquí, `127.0.0.1` es el propio Codespace.

```bash
curl -i "http://127.0.0.1:3004/events/1/registrations/usuario-02"
```

Espera **HTTP 200** y el título **Festival de otoño**. En una base recién preparada, aparece `"registration":null`. Para inscribir al usuario, ejecuta:

```bash
curl -i -X POST "http://127.0.0.1:3004/events/1/registrations/usuario-02"
```

**Antes de terminar**, comprueba **201** en el primer POST, **409** si lo repites y **200 con la inscripción** al repetir el GET. Si ya habías inscrito al usuario, puedes empezar verificando la inscripción con GET.

Para ver el GET en otra pestaña del navegador, abre **Ports** en VS Code, localiza **3004** y pulsa **Open in Browser**. Si el puerto aún no aparece, añádelo con **Forward a Port**. Mantén la visibilidad en **Private**. Añade `/events/1/registrations/usuario-02` al final de la URL que abra GitHub. [Reenvío de puertos en Codespaces](https://docs.github.com/es/codespaces/developing-in-a-codespace/forwarding-ports-in-your-codespace)

## Compara GetItem con el SELECT en el Codespace

En la tercera terminal, comprueba si está disponible AWS CLI:

```bash
aws --version
```

Para este apartado necesitas AWS CLI v2 **en el Codespace**. Si no está instalada, sigue la sección Linux de la guía oficial. [Instalar AWS CLI v2 en Linux](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html)

Pega esta función una vez en la tercera terminal. Usa credenciales ficticias durante el comando. Los dos ejemplos apuntan al puerto de DynamoDB Local con `--endpoint-url`.

```bash
aws_local() (
  unset AWS_PROFILE AWS_DEFAULT_PROFILE AWS_SESSION_TOKEN AWS_SECURITY_TOKEN
  export AWS_ACCESS_KEY_ID=local AWS_SECRET_ACCESS_KEY=local
  aws --region us-east-1 --no-cli-pager "$@"
)
```

```bash
aws_local dynamodb get-item \
  --endpoint-url http://127.0.0.1:8000 \
  --table-name FCI_EVENTOS_local \
  --key '{"EVENT_ID":{"N":"1"}}' \
  --query Item --output json
```

```bash
aws_local dynamodb execute-statement \
  --endpoint-url http://127.0.0.1:8000 \
  --statement 'SELECT * FROM "FCI_EVENTOS_local" WHERE EVENT_ID = 1' \
  --query 'Items[0]' --output json
```

**Comprueba el resultado.** En las dos salidas, `EVENT_ID` vale **1** y `TITLE` es **Festival de otoño**.
